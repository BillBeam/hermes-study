## 4. 开工杂项:BLOCK-DRIFT 清零并升格

R8C 给校验器补上全块比对后扫出历史积压。本轮全语料实测 **116 处**
(R8C 报 115,差 1 是**口径差不是回归**:R8C 的 115 是 notes 侧统计,
chapters 侧另有 4 处它在报告 §2.2 单列了)。分五组并行清完,**116 → 0**。

**形态分布本身是结论**:

| 形态 | 占比 | |
|---|---|---|
| 行尾被截短 | 最多 | 摘录把基线某行砍掉后半句,其后每行错位 |
| 多行调用被压成一行 | 次之 | "看起来更清爽"的改写 |
| 无效的行内省略号 | 少数 | `...))` / `[中略]` / `# 某句 ...` —— 都不匹配省略标记正则 |
| 中段整段省略无标记 | 少数 | 漏抄几行注释 |
| **摘录对源码作了假声明** | **1 处** | 凭空补的 `"""` 收尾,暗示 docstring 在第 10 行结束,实际到第 29 行 |

**115 / 116 靠回抄基线原文即可解决。** 所以这个关卡防的不是"作者把散文当代码贴",
而是**"作者手抄代码时抄漏了半行"**——机器该抓、人工评审抓不住的那一类。

**升格**:`block_drift` 由提示改为阻断(计入失败、退出码 1),已用一份**故意写错的探针**
验证关卡真会拦(exit 1),真实关卡范围仍 exit 0。分期沿用引用校验自己的先例
(R7C 加、R8A 升格):**一个对着自己没造成的积压狂叫的关卡,只会教会作者忽略它。**
CLAUDE.md 同步写入契约、合法省略标记形状,以及"优先拆成两个带锚点的块"的取舍。

**升格当场就抓到了三次自己人**:主线写 `notes/r8d-90-rulings.md` 时 4 处 MISMATCH + 1 处 BLOCK-DRIFT、
补漏卷 2 处锚点漂移、覆盖复核卷 2 处(见 §4.1)——**全部由关卡而非人工发现**。

## 6. 主线复核子代理条目

制度要求不照单全收。四条最强断言全部复核,**三条通过、一条收窄**;
另两条 ■ 复核通过、其中一条**改了归类**。详见 `notes/r8d-90-rulings.md` §3.5。

- **通过**:`rebuild_venv` 是死桩(声明 `-> bool`,函数体只有一条求值即丢的表达式,
  全仓唯一命中是它自己的 def);`UpdateLock.acquire()` 非原子(读 `:245` / 写 `:253`);
  `mcp_serve` 的两个审批工具结构性失效(**负结论**,主线独立复搜 20 处命中逐一归类,
  生产代码零写入点,而 5 个测试全绿正因为它们直接注入私有 dict)。
- **收窄**:"7 条互相独立的动态导入通道"——主线用**子代理给出的同一条命令**重跑,
  去重文件数是 **12** 而非 7。逐个判定后,7 条在"第三方代码准入通道"口径下成立,
  但底稿措辞比它验证的范围宽。
  *这一条正是"全称断言必须写搜索面"起作用的样子:因为搜索面写了,主线才能重跑并发现口径差。*
- **改归类**:`PYTEST_CURRENT_TEST` 让受管层整层消失——现象属实,但把整段 docstring
  一并判定后确认这是**写明了意图的测试接缝**(防 CI 机器上的真实策略污染测试),
  不是疏忽。仍记 ■,归类为"**测试接缝具备生产后果**":这一层自称
  "IT-pushed, user-immutable",而它要约束的对象正是能设环境变量的那个用户。

三条结构性欠账:

**(一)171 个 L1 文件 / 104,656 行从未被认领。** 这比 R8D 自己的 L1 量还大一倍半。
成因:分层规则里 `agent/` 与 `tools/` 两条**兜底规则**的 `round` 列写的是**区间占位符**
(`R3-R7` / `R3-R4`),注释说"其余文件在后续轮次开工时显式定轮"——那件事 R5 之后一次也没发生。
于是形成一条干净的分界线:**被规则表点名的文件读了,只在计划散文里出现的没读。**

其中最刺眼的是 R6。R1 的轮次表给 R6 的定义是"记忆-技能-学习闭环",
点名了 `learn_prompt`、`learning_graph*`、`insights`、`curator*`、
"skills 全链(tool/manager/hub/guard/usage/…)"。实际:**记忆读完了,技能和学习一个没读**
——`agent/learn_prompt.py`、`agent/learning_graph.py`、`agent/insights.py`、`agent/curator.py`、
`tools/skills_hub.py`(4,432 行)、`tools/skills_tool.py`、`tools/skill_manager_tool.py`、
`tools/skill_usage.py` 全部仍是 `R1-inventoried`。
而 R1 对 R6 的定位原话是"**本仓库最独特的卖点**"。

**处置**:兜底规则的 `round` 改为显式的 **`UNCLAIMED`**,任何一轮按 `round` 报数时它都会自己跳出来;
顺手补记两个当年被 R4/R5 读了但规则表没跟着改的文件,让计划列与事实列对齐。
**不由 R8D 顺手吃掉**——理由与 §1 同源:硬塞进来只会重演兜底桶本身的错误,**用容器代替判断**。

**(二)L3 整层从未开工。** 1,895 文件 / 602,085 行,台账里 `*-cataloged` 状态**一个都没有**。
R6 计划的"skills/ 与 optional-skills/ 编目"、R11 的"docs/ 设计文档全读"都在这一层。

**(三)R6 的 L2 遗留。** `plugins/**` 243 文件 / 116,078 行仍未开工,而 R6 已宣告完成。

### 7.1 这个洞怎么活过了八轮

**因为每轮的验收都是自洽的。** 覆盖守恒查的是 `layer` 列加总——这 171 个文件一直老实计在 L1 里,
加总永远等于 2,608,452,**分层快照永远是绿的,它压根不看有没有读**。
`status` 列才是唯一可观测指标,而 R7 到 R8B 之间五轮没人报它
(R8-fix 已因此把"必报 `R1-inventoried` 剩余"写进 CLAUDE.md)。
但**即使报了总数也看不出这个洞**:8,096 这个数被 3,381 个 LT 与 560 个 L4 撑得很大,
171 个核心 L1 文件淹没在里面。**总数掩盖结构**——所以 §2.2 起按性质拆开报。

方法学上,这是本项目对 hermes-agent 的核心判据**掉头指向自己**的一次应用:
我们对作者说"README 是自绘地图,与代码冲突时以代码为准";
那么**我们的轮次规划表也是自绘地图,与 `assign_layers.py` 冲突时以规则为准**——
而规则说,这 171 个文件没有任何一轮认领过。

### 8.1 R11 是否需要拆分:**需要,拆成 R11A / R11B**

三条理由:

1. **是两种不同的活。** R11A 读的是构建/测试/CI/发布机器(`scripts/`、`docker/`、`nix/`、`.github/`),
   L2 结构级**读代码**;R11B 是 L3 **编目**近 26 万行散文,外加"文档-代码全面对照"。
   一个是读实现,一个是判断断言真伪——放一轮里必然有一半被草草带过。
2. **R11A 单独就是一个满轮。** 43,365 行,与 R8B 的 43,539 行同级,
   与 R1 定的"每轮 L1 3–6 万行"预算相当。
3. **R11B 承担一件别处没有的职责:▲ 台账的总收口。** `website/docs` 是全项目
   ▲/◇/◎ 记号所判定的那张"作者自绘地图"。R2–R8D 每轮都是**遇到什么判什么**,

**这个切法还有一个独立的旁证**:R11A/R11B 的边界与 L2/L3 的层边界**完全重合**
(141 个 L2 文件恰好是 `scripts`+`nix`+`.github`+`docker`+根配置,
787 个 L3 恰好是 `website`+`locales`+`docs`+`.plans`)。
两个用不同方法算出来的边界重合,说明这不是硬切的。

### 8.2 R12 的前置条件(本轮新增的判断)

R12 的定位是"不产生新文件,把 R2–R11 的成品章装订成《设计蓝图》"。
但成品章目前只覆盖到 L1 的 78.6%,而 171 个无主 L1 文件里含

这正是 R1 自己写下的达成判据("L1 全部 deep-read + 综合轮产出设计手册 = 达成目标 1、2")。
按现状,R12 若如期开工,蓝图会缺一块它自己声明必须有的内容。
