### 7.1 主线全链复核的一条 ■(本轮最重)

**■-01 网关 bearer 会被挂到任意主机。** 判断「这个媒体 URL 要不要带我们的凭据」用的是子串包含
(`gateway/relay/media.py:92`),这个布尔直接决定挂不挂 `Authorization`(`:164`),
而 URL 来自**入站事件**(`gateway/relay/adapter.py:461`)。
判据:一条带 `https://attacker.example/relay/media/x` 的入站事件 → 网关 bearer 送到 attacker.example。
**作者本意是对的且写在同一函数说明里**(`:449` 期望 `{connector}/relay/media/{id}` 这种带主机前缀的形状),
实现退化成一次 `in`。

**威胁边界按主线口径收窄**,不跟子代理的表述放大:准确表述是
**「任何能向该网关投递入站事件媒体 URL 的一方」**,比「已拿到本地权限」低得多,
但也不是「任意互联网用户」。

### 7.4 结构性结论

把本轮的缺陷排在一起,它们不是孤立的 bug:

| 守卫 | 判据是什么 | 谁从旁边走过去 |
|---|---|---|
| 审批闸门 | 「这是一次工具调用吗」 | SKILL.md 内联 shell,直接开子进程 |
| 沙箱密钥清洗 | 「变量名含密钥子串吗」 | 透传名单命中即跳过,走不到清洗 |
| 安全扫描器 | 123 条正文模式 | 让文本变成执行的那个记号不在表里 |
| 验证门 | `frozenset({"write_file", "patch"})` | `sed -i`、`execute_code`、MCP 文件工具 |
| SSRF 守卫 | 「调用方走没走那个封装」 | 从远端 JSON 取 URL 的那一处没走 |
| 网关凭据 | 「URL 含 `/relay/media/` 吗」 | 任意主机只要 URL 里有这个子串 |

**守卫都在,判据全是名单,而扩展面天然长在名单之外。**
名单描述的是「我知道的那些情况」,而扩展面存在的意义恰恰是产生我还不知道的情况。

**唯一一个把守卫问到位的扩展面是委派**:子 agent 不能绕过审批
(`delegation.subagent_auto_approve` 默认 `False`,关闭时装的是**拒绝式**回调),
深度默认锁死 1 层,工具集只减不增。这条**负结论**必须写进结论——
否则本轮会被读成「这个代码库到处漏」,而事实是**最像会漏的那一个反而做得最严**。

   **实测 `file` 是有的**。准确集合:文档列 30 个键、`TOOLSETS` 实有 58 个、
