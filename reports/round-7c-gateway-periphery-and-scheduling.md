# Round 7C 报告 · 网关外围面与定时调度

**一句话结论:网关外围面与定时调度学透,定案 41 条。**

头条发现:**同一个 bug 在三个互不相关的地方各犯了一次,三次都静默、三次都有绿测试。**
`/platform` 读 `event.content`、`/footer` 读 `event.message`、关停落盘读 `event.session_id`
—— 而消息事件对象**这三个字段一个都没有**(语法树全量枚举,`gateway/platforms/base.py:2054
@ 863e313` 起 20 个字段)。`getattr(o, "name", default)` 不报错、`or ""` 兜底不出声、
测试用 `MagicMock` 把不存在的字段假造了出来,三者叠加让字段名笔误活到了生产。
后果分别是:`/platform` 的参数永远解析不出来、`/footer status` 这条纯查询命令**会翻转开关**、
以及**关停时落盘保下来的消息永远回不到数据库**(而这个机制的存在理由正是"关停不丢消息")。

第二发现同源同型:**scale-to-zero 在生产中从不触发**。判定被抽成了漂亮的无副作用纯函数,
但调用方把 `_background_tasks` 当成"后台工作集合"喂给它 —— 那其实是**常驻守护任务注册表**,
里面躺着 8 个永不结束的 watcher,**而 scale-to-zero 自己的 watcher 也在其中**:
它一旦启动,就成了让自己永远睡不着的原因。12 个单元测试全绿,因为测试把那个集合置空了。

## 3. 主要学习成果(成品章 `chapters/r7c-gateway-periphery-and-scheduling.md`)

1. **这一簇不是流水线,是长跑进程的四个外部输入面 + 一个输出面**:人敲的 slash 命令、
   定时表、外部监督者(systemd)、带外事件(看板)。会话核心只管"用户说了句话",
   这一圈管"除此之外的一切"。
2. **定时调度的正确性支点是一句话:执行**前**就把下次触发时间推进掉。**
   崩溃、重启、多副本都靠它。它把 at-most-once 从分布式难题降级成一次文件写 ——
   **并且这是个显式取舍**(少发一次好过发两次),应写进设计文档而非埋在实现里。
3. **配对码那道门只能从外面开**:批准函数全仓 4 个调用点全在已认证侧,
   入站消息路径零调用。码不存明文(每条独立盐 + SHA-256)、常数时间比较、
   **锁定检查排在条目查找之前**(否则两种失败的响应差异本身就是枚举信道)。
4. **关停是一场和外部计时器的赛跑**,而**内部看门狗输了**:关停看门狗设为"排水预算+60s",
   systemd 的 `TimeoutStopSec` 是 `max(60, 排水预算+30)` —— 排水预算只要大于 0,
   SIGKILL 必定先到,看门狗是死代码。仓库有一个"检查计时对齐"的自检函数,
   但它校验的余量(30s)和看门狗用的余量(60s)不是同一个,**于是永远不告警**。
5. **存活判据用"事件循环有没有按时醒来",且判断方与处决方分离** ——
   被监控者只停止上报,由 systemd 决定杀不杀。这是异步单线程模型下唯一有意义的存活判据。
6. **带外注入的判据只有一句:这条输入能不能等到下一轮?** 等不了 → steer 中途注入
   (人工评论);等得了 → 合成事件排队(卡片终态)。

### 4.4 规律:R7/R7B 五条全部复现,新增三条

1. **docstring 的腐烂有两种形态,时间腐烂比路径腐烂更隐蔽。** R7B 发现的是路径腐烂
   (文件搬家);本轮发现**时间腐烂** —— `status.py` 的注释末句是
   "will be useful **when we add** named profiles"(将来时,而该功能早已上线),
   slash 模块注释说 "42 of them (~3,200 LOC)"(实测 52 个 / 5,693 行)。
   **判据:模块 docstring 里出现将来时或具体计数,基本可以断定它已过期。**
2. **测试通过 ≠ 机制在生产中工作,而且测试会把 bug 固化成规格。**
   本轮三例的共同点是**测试构造的对象形状与生产构造点不一致**
   (`MagicMock` 补字段 / 注册表置空 / monkeypatch 掉被测谓词)。
   R7 的 `memory_monitor.py` 是"有测试零调用点",本轮更进一步:
   **有测试、有调用点、调用点在生产中恒失败。**
3. **接线核查要查"有没有人调用它的方法",不是"有没有人提到它"。**

## 8. 本轮新增工具:`scripts/verify_citations.py`

R7B 的教训是"定稿前抽查修正了 5 处行号偏移,这类偏移在纯子代理流程里没有第二道关"。
本轮把这道关**做成了脚本**:它扫描每一条后面跟着代码块的 `路径:行号` 引用,
把代码块首行与基线文件对应行**逐字比对**,不匹配时报出真实行号;
`--fix` 可自动改写无歧义的那些。

**实战效果:在全部 R7C 产出的 2,531 条引用中,抓出并修正了约 60 处行号漂移**(多为 ±1),
另揪出 3 处**非原文引用**(用 `...` 省略了中间代码,违反"代码原文块"标准,已改回原文)
与 5 处只写文件名不写路径的引用。
**它还抓到了主线自己的 3 处错误** —— 我在写定案卷时从子代理摘要里直接抄了三段注释,
没有回源复核,三段的起始行号都不对。这恰好证明了这道关的必要性:
**主线复核子代理,谁复核主线?**

脚本本身也在本轮迭代了四次,每次都由一类真实的误报驱动(围栏内的图示标签不是引用;
代码块自带的 `# 路径:行号` 定位注释才是权威;一行上有多条引用时应逐个尝试;
引用本仓库自己的历史产出也应被解析)。**最终状态:本轮全部产出(14 篇底稿 + 主线卷 +
定案卷 + 测试卷 + 成品章 + 本报告)共 2,531 条引用,其中 802 条带代码块、
全部逐字匹配基线通过;其余 1,729 条是指向某个区段的散文引用,脚本记为未校验。**
