## 1. 其七:「结清的单一落点」这条制度是否已真正落实

### 1.1 结论:在册,未落实

R11B 判定「移交项反复漏账」的根因**不是扫得不够宽,而是结清没有单一落点**,
并据此入册了新规则(`CLAUDE.md` 的「结清的单一落点」一条)。R11B 自己**遵守了**这条规则:
21 条移交逐条定案,写进报告 §5 与 `notes/r11b-90-handover-rulings.md`。

**而普查一条都没读到。**

`reports/round-11b-review-and-reconciliation.md:343 @ 863e313`

```
| 移交项 | 处置 |
```

这张表就是 R11B 按新规矩落的那个「单一落点」。用 R11B 自己那版普查的解析器去读它:

```verify
cd /home/user/hermes-study && python3 - <<'PY'
import sys, pathlib
sys.path.insert(0, "data/r11b/probes")
import handover_census_r11b as H
for f in ["reports/round-11b-review-and-reconciliation.md",
          "notes/r11b-90-handover-rulings.md"]:
    ev = H.scan(pathlib.Path(f))
    kinds = {}
    for k, i, n in ev:
        kinds[k] = kinds.get(k, 0) + 1
    print(f"{f}: {kinds or '解析出 0 条'}")
PY
```

```text
reports/round-11b-review-and-reconciliation.md: 解析出 0 条
notes/r11b-90-handover-rulings.md: {'handover': 8}
```

两个数都要读懂:

- **报告那张表解析出 0 条。** 判 ruling 的关键词是「处置**结论**」「结论」「复核结果」,
  而这张表的表头是「处置」。表头认不出 → `kind = None` → 整张表被 `continue` 掉,
  **既不报错也不计数**。21 条定案在账面上完全不存在。
- **底稿那张表解析出 8 条,全部记成 `handover`。** 它的表头是
  `| 移交项 | 去向 | 本轮处置 |`,而分类器先看「去向」——于是**一张定案表被读成了一次新的移交**,
  连「去向」列的旧值一起原样登记回去。**定案表把它定的案又重新打开了。**

这两条合起来,回答了本轮的其七:**制度在册,但没有落实**——不是作者没照做,
是**唯一能观测「做没做」的那个东西读不到它**。

### 1.2 第三处:片内铸的号从来没进过语料

R11B 版的同轮底稿是这么找的:

`data/r11b/probes/handover_census_r11b.py:56 @ 863e313`

```
    pats = (f"r{rkey}-9*-*ruling*.md", f"r{rkey}-9*-*handover*.md")
```

而 R11B 自己的报告 §9 写明移交「见各底稿 `## 移交` 节」,列了 8 份文件,
其中 6 份不匹配这个模式。**本轮要清的两笔真欠账正好就在那 6 份里**:
`H-R11B-A-c` / `-d` 立在 `notes/r11b-raw-rulings-census.md`,
用 R11B 口径去搜,**一条都看不到**。

这一处**不是**「又一次该扩扫描面」——R11B 驳回扩面驳得对,但它驳的是
「靠不断追加目录去找**结清**」。这里缺的是**发现面**:一条案子铸在哪儿,
决定它能不能被看见,而**铸号发生在片里是制度自己承认的**
(案号纪律明写「片内铸号必须带片标识」)。
所以本轮的改法是**把两件事分开**:结清落点不放宽(仍是所属轮次的移交/定案表),
发现面覆盖该轮全部底稿。

### 1.4 一次当场翻车的自我否定(必须写出来)

改普查时我想顺手做一件看起来很自然的事:**用一份「续转类词根」表自动把
「落在定案表里但其实没关闭」的条目按住**。R11B §5 确实有明写不关闭的条目
(`H-R9B-f`「维持推定,不关闭」),只看「这一行在定案表里」就判 CLOSED 会漏掉它们。

**首次运行 13 条命中里 6 条是假阳性,全部栽在同一个坑:短语被从它的否定里摘了出来。**

| 条目 | 命中的词 | 它所在的原句 | 原句的意思 |
|---|---|---|---|
| `H-R10E-c`、`H-R8C-a`、`H-R8C-e`、`H-R8C-g`、`H-R9A-a` | 续转 | 小节标题「移交项定案(逐条给结论,**无一「续转」了事**)」 | **恰好相反** |
| `H-R8B-b` | 续转 | 「**关闭**,不再续转」 | 已关闭 |
| `H-R9B-c` | 续转 | 「**关闭并加重**;…不再续转」 | 已关闭 |

这就是 `CLAUDE.md` 里记了两轮的那条教训换了个部件:r4-90 写进定案的自检 grep 用
`iron` 匹配到了 `env`**`iron`**`ment`。**一个会把「无一续转」读成「续转」的判据,
拿去关闭调查是危险的。**

**处置:不采用。** 机械口径只保留一条没有解释空间的(「该案最后一次出现在移交表
还是定案表」),词根命中改为**只入 REVIEW 队列、不改判**,并把命中的词与原文一起打出来,
让否定语境当场可见。**判开闭是人的事,普查的事是别让任何一条从眼前消失。**
已入册 `CLAUDE.md`「机械判据不得用词根去判开/闭这类语义」。

## 2. 其六:案号纪律违例的处置

### 2.1 H-R11A-f 结清(台账 round 归属)

R11A 有意未改,理由是这 243 个 L2「分散在一条兜底规则与两条显式点名规则之间,
**只改兜底会留 16 个不一致**,而『显式点名却没做』与『兜底桶没人认领』是两种不同的失败」。

**裁定:那 16 个不是不一致,是另一种失败,应当保留可见。** 于是给两种失败**两个不同的
`round` 值**,而不是把它们合并成一个数:

`scripts/assign_layers.py:622 @ 863e313`

```
    ("plugins/**", "L2", "UNCLAIMED"),
```

- 兜底 **227 个 / 114,899 行** → `UNCLAIMED`(R6 从未点名过它们,是「没人认领」);
- 显式点名的 **16 个**(memory 的 8 个 `README.md` + 8 个 `plugin.yaml`)→ **留 `R6`**。
  R6 的规则注释明写「README/plugin.yaml 留 L2(文档与元数据,结构级即可)」,
  即**点名了却没做**。

保留 `R6` 与 R11B 不改那 38 个文件 `status` 的理由同源:**改掉就抹掉了「哪一轮原本
声称要做」这条线索**,而正是这条线索让缺口能被发现。两桶此后各自可数:

### 2.2 片 B1 五条无轮次前缀的移交号

R11B 自陈:片 B1 的 5 条铸成 `H-B1-a…e`,**没带轮次前缀**,与同轮新定的案号纪律相抵;
R11B 判「规则是在派发**之后**才定的,故不追改片 B1 的底稿(清账只更正记录),
但下一轮若也有『片 B1』就会撞号」。

**本轮裁定:不改底稿,建别名,并把别名登记在案。** 三条理由:

1. R11B 的判断是对的——**规则不溯及既往**,而「清账只更正记录,不改变已定案结论的实质」
   是本项目明写的边界。改掉 `notes/r11b-raw-backlog-r7b.md` 的正文号,
   会让那份底稿看起来一直合规,这正是禁止的那种改法。
2. 但**撞号风险是真的**,而它不需要靠改历史来消除:本项目处理重复案号的既有做法
   就是「**别名不删,建别名表**」(R11B 定的 7 条合并规则第 1 条)。
3. 别名一旦登记,普查与下一轮都以规范号为准,历史底稿的原号仍可溯源。

**别名表**(规范号 → 历史号,两侧都有效;引用时用规范号):

| 规范号 | 历史号 | 立项处 | 一句话现象 |
|---|---|---|---|
| `H-R11B-B1-a` | `H-B1-a` | `notes/r11b-raw-backlog-r7b.md:2604`:`| H-B1-a | R11B 主线 / 成品章 |` | 片 B1 铸号未带轮次前缀,五条同源 |
| `H-R11B-B1-b` | `H-B1-b` | 同上 | 同上 |
| `H-R11B-B1-c` | `H-B1-c` | 同上 | 同上 |
| `H-R11B-B1-d` | `H-B1-d` | 同上 | 同上 |
| `H-R11B-B1-e` | `H-B1-e` | 同上 | 同上 |

*为什么这条值得单独占一节:R11B 把它写在报告 §9 的一个脚注里,措辞是「写在这里让它
别再无声发生」。**而脚注不是账**——普查读表格行,不读脚注。本轮把它挪进表格,
它才第一次成为一条可被机械看见的记录。这本身就是其七那条结论的又一个实例。*
