## 2. 证据格式(机械校验,过不了就是没交付)

主线会对你的底稿跑:

```bash
python3 scripts/verify_citations.py /home/user/hermes-agent notes/r11a-raw-<片名>.md
python3 scripts/verify_evidence_commands.py notes/r11a-raw-<片名>.md
```

必须 **0 MISMATCH / 0 BLOCK-DRIFT / 0 TABLE-DRIFT / 0 TABLE-OUT-OF-RANGE / 0 differing**。规则:

- **锚点写成 `路径:行号 @ 863e313`,单独成行,放在代码块/引用块之前**,不放块后。
  校验器按「锚点 → 紧跟其后的块」配对;写在块后 = 一条都不会被校验。
- ```` ``` ```` 围栏块 = **逐字源码摘录**,**整块每一行**都要与基线逐字一致
  (空白不敏感、文字必须一致)。要跳段就**拆成两个各自带锚点的块**,
  不要打省略号——`...))`、`# 某句 ...` 这类**不是**合法省略标记。
- 不是源码的块(命令输出、你自己的判断表)必须用 ```` ```text ````、```` ```console ````、
  ```` ```verify ```` 显式标注。**声明,不靠脚本猜。**
- **表格里的锚点**要被校验,必须写成「锚点 + **紧跟其后**的反引号摘录」:
  `` `scripts/release.py:42`:`def main() -> int:` `` 或 `` `nix/lib.nix:42` 的 `mkHermes` ``。
  只认紧跟的那一个片段,不扫全行。
- **扩展名白名单**:`py mdx md yaml yml toml c h sh json tsx ts mjs js nix rs txt`。
  **R11A 新增**:无扩展名文件也能当锚点了,但只限一份显式名单
  (`.gitignore` `.dockerignore` `.npmrc` `Dockerfile` `Makefile` `LICENSE` `NOTICE`
  以及 `docker/s6-rc.d/` 下的 `run` `type` `finish` `base` 等)。
  **`run`/`type`/`base` 这类词必须写全路径**(如
  `docker/s6-rc.d/main-hermes/run:23-26`),写成裸 `run:23` 不会被认作锚点。
  不在两份名单上的扩展名(`.ps1`、`.cmd`、`.service`、`.desktop` 等)
  **不会被识别成锚点**,也就不受机械保护——引用这类文件时**照写锚点**(读者要用),
  但关键断言尽量落在受保护的扩展名上。
  *注意本轮 A 片有 `scripts/install.ps1`(4,262 行)、B 片有大量 `.yml`——
  `.yml` 在名单上,`.ps1` 不在。*
- **裸文件名解析不了**:写 `ci.yml:42` 没用。**一律写全路径**(`.github/workflows/ci.yml:42`)。

## 3. shell 命令即证据(**本轮起阻断**)

凡把 shell 命令写进证据,**必须是重跑能复现该结论的那一条**,用 ```` ```verify ```` 标注。

**本轮新规(结清 H-R10B-g):凡正文里出现由某条命令得出的数**("实测 N 处""共 M 个"
"零命中"),**那条命令必须把输出贴在紧跟其后的 ```` ```text ```` 块里**:

    ```verify
    cd /home/user/hermes-agent && grep -c 'foo' scripts/release.py
    ```

    ```text
    7
    ```

主线会**重跑**每一条并逐字比对。**手工裁剪过的输出会被抓出来**——上一轮首次运行
就在当轮底稿抓到 4 处,其中 1 处是一段**从未由该命令产生过**的 diff,数字看起来完全合理。
不想钉数的命令(给读者去跑的)可以不配 ```` ```text ````,但那样它也不算证据。

**输出很长时,把命令收敛到只打印你要钉的那个数**(`| wc -l`、`| tail -3`),
不要贴几百行再手工删——那正是会被抓出来的形态。

## 4. 负结论的成本

"全仓没有 X""没有第三个调用方"这类**全称否定**,可信度等于一次 grep 的完备性。
写下一条负结论时**必须把搜索面写出来**(搜了什么、什么模式、排除了什么),
否则它只是"我没看见"的另一种说法。

## 5. 交付判据

### L2 片(A、B)——沿用 R10 定的五条

| # | 判据 | 主线怎么复核 |
|---|---|---|
| **1 点名到位** | 片内**每个**文件至少出现一次**全路径** + 一句话角色;同型薄文件可归组,**组内仍逐个列全路径** | `data/r10/probes/named_coverage.py` 实测零命中数 |
| **2 接缝穷举** | 每个对外接缝(CI job 矩阵 / 安装器支持的平台与参数 / Nix 输出面 / s6 服务与依赖表 / 环境变量面)**逐项列全、不抽样**,并给出**机械枚举命令**与条数 | 重跑你给的枚举命令核条数 |
| **3 端到端链** | 至少一条「触发 → 脚本 → 产物 → 落地」的链,**逐跳带锚点** | 顺着锚点走一遍 |
| **4 逐字取证** | 至少 **5** 个围栏块是逐字源码摘录,钉在关键跳上 | BLOCK-DRIFT 全块比对 |
| **5 记号** | 至少 1 条 ■/▲/◇/◎ 带锚点,或带搜索面的负结论 | 抽验 |

### L3 片(C)——沿用 R10B 定的五条

| # | 判据 | 主线怎么复核 |
|---|---|---|
| **L3-1 用途到位** | 片内**每个**文件至少出现一次**全路径** + 一句话「它是什么、谁读它」。同型薄文件可归组,**组内仍逐个列全路径** | 全路径零命中 + 裸文件名零命中,均须为 0 |
| **L3-2 形态账** | 按**形态**分组(如「技能说明书」「参考资料」「可执行脚本」「清单/元数据」),每组给**机械可复算的规模数**与**得出它的命令**。**不要求穷举接口面** | 重跑命令核数字 |
| **L3-3 一条真链** | 至少一条「这份东西被谁读 → 在哪装配 → 缺了会怎样」的链,**逐跳带锚点**。技能库的读取方在片**外**(如 `scripts/build_skills_index.py`、`tools/skills_hub.py`),**允许并鼓励引用片外文件来完成这条链** | 顺锚点走一遍 |
| **L3-4 逐字取证下限** | 至少 **2** 个围栏块是逐字源码摘录,**且钉在 L3-3 那条链的关键跳上**,不是随手摘一段数据 | BLOCK-DRIFT + 人工看它摘的是不是链上的跳 |
| **L3-5 记号或有搜索面的负结论** | 至少一条 ■/▲/◇/◎ 带锚点;**或**明确写「本簇未发现」并给出搜索面 | 抽验 |

**L3 不是 L2 的削弱版,是换了一组问题。** L3 会退化成的样子不是"读得浅",
是**"我列了个目录"**;挡住它的是**规模数与算它的命令**——目录谁都能列,
"这个技能有几个 reference 文件、命令是什么"列不出来就是没打开过。
