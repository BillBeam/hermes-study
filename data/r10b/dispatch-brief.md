## 2. 证据格式(机械校验,过不了就是没交付)

主线会对你的底稿跑:

```bash
python3 scripts/verify_citations.py /home/user/hermes-agent notes/r10b-raw-<片名>.md
```

必须 **0 MISMATCH / 0 BLOCK-DRIFT / 0 TABLE-DRIFT / 0 TABLE-OUT-OF-RANGE**。规则:

- **锚点写成 `路径:行号 @ 863e313`,单独成行,放在代码块/引用块之前**,不放块后。
  校验器按「锚点 → 紧跟其后的块」配对;写在块后 = 一条都不会被校验。
- ```` ``` ```` 围栏块 = **逐字源码摘录**,**整块每一行**都要与基线逐字一致
  (空白不敏感、文字必须一致)。要跳段就**拆成两个各自带锚点的块**,
  不要打省略号——`...))`、`# 某句 ...` 这类**不是**合法省略标记。
- 不是源码的块(命令输出、你自己的判断表)必须用 ```` ```text ````、```` ```console ````、
  ```` ```verify ```` 显式标注。**声明,不靠脚本猜。**
- **表格里的锚点**要被校验,必须写成「锚点 + **紧跟其后**的反引号摘录」:
  `` `apps/desktop/src/app/chat/index.tsx:42`:`const foo = 1` `` 或
  `` `path.ts:42` 的 `funcName` ``。只认紧跟的那一个片段,不扫全行。
- **写进底稿的 shell 命令必须是重跑能复现该结论的那一条**,用 ```` ```verify ```` 标注。
  一条重跑给出相反结果的命令比不写更糟。
- **扩展名白名单**(R10B 刚扩过):`py mdx md yaml yml toml c h sh json tsx ts mjs js nix rs txt`。
  不在表上的扩展名(如 `.css`、`.html`、`.rs` 以外的 Rust 产物、`.svg`)**不会被识别成锚点**,
  也就不会被校验——引用这类文件时**照写锚点**(读者要用),但心里清楚它不受机械保护,
  关键断言尽量落在受保护的扩展名上。
- **裸文件名解析不了**:写 `index.tsx:42` 没用(基线里同名文件几十个)。**一律写全路径。**

## 3. 交付判据

### L2 片(A–H、J、K)——沿用 R10 定的五条

| # | 判据 | 主线怎么复核 |
|---|---|---|
| **1 点名到位** | 片内**每个**文件至少出现一次**全路径** + 一句话角色;同型薄文件可归组,**组内仍逐个列全路径** | `data/r10/probes/named_coverage.py` 实测零命中数 |
| **2 接缝穷举** | 每个对外接缝(IPC 通道表 / 路由表 / store action 面 / 组件 props 契约 / 导出面 / 事件表)**逐项列全、不抽样**,并给出**机械枚举命令**与条数 | 重跑你给的枚举命令核条数 |
| **3 端到端链** | 至少一条「用户动作 → 组件 → 状态 → 协议 → 内核」的链,**逐跳带锚点** | 顺着锚点走一遍 |
| **4 逐字取证** | 至少 2 个围栏块是逐字源码摘录 | BLOCK-DRIFT 全块比对 |
| **5 记号** | 至少一条 ■/▲/◇/◎ 带锚点 | 抽验定性是否被证据支撑 |

**判据 2 是重心。** L2 与 L1 的差别不是「读得浅」,是**「读接口面而不读实现体」**——
可以不读实现,**但不能抽样接口**。接口面一抽样,「结构级理解」就退化成「看过几个文件」。
**做不到就明说做到了几成**,不要粉饰;自报未达标会被如实记在案,粉饰会被复核撞破。

## 4. 记号约定

- **■** 代码缺陷 · **▲** 文档所述与代码**矛盾** · **◇** 代码有、文档无 · **◎** 文档成立但显著保守

## 5. 负结论的成本

「全仓没有 X」「没有第三个调用方」这类**全称否定**,可信度等于一次 grep 的完备性,
**没有任何机制校验它**。写下一条负结论时**必须把搜索面写出来**——搜了什么、
用什么模式、排除了什么——否则它只是「我没看见」的另一种说法。

## 6. 测试作为行为规格

`apps/desktop` 的 vitest 有两个 project(`apps/desktop/vitest.config.ts`):
`ui` 是 **jsdom** 环境跑 `src/**/*.test.{ts,tsx}`,`electron` 是 **node** 环境跑
`electron/**/*.test.ts` 与 `scripts/**.test.{ts,mjs}`。**两个都不需要 Electron 二进制。**
只有 `e2e/` 的 Playwright spec 需要真 Electron + 浏览器。

主线已在**基线之外**准备好可跑环境(`git archive` 导出的副本,不污染基线):

```bash
cd /home/user/r10b-ts/hermes-agent/apps/desktop && npx vitest run --project ui
```

**你可以跑测试(不要装包)。** 与你这一片相关的测试是**行为规格**:
它钉住的行为就是作者承诺的行为。引用测试时同样带锚点。
**报测试数时三个数都报:passed / failed / skipped**,并且**整文件跳过或零执行
(收集错误、`importorskip`、`describe.skip`)要逐个点名并报出掩盖了多少用例**——
一个静默零执行的文件在汇总里和「通过」长得一模一样。
