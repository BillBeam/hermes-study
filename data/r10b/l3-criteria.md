# L3 交付判据(R10B 定义,与 R10 定的 L2 五条并列)

> **为什么需要它。** 台账把全仓分五层:L1 机制精读 / L2 结构级理解 / L3 知悉用途 /
> L4 有理由排除 / LT 测试。L1 有天然判据(逐机制、断言带行号),R10 给 L2 定了五条。
> **L3 到 R10B 之前是零先例**——1,895 个文件 / 602,085 行,`status` 清一色
> `R1-inventoried`,从没有人说过「知悉用途」交付到什么程度算读过。
> 没有判据,把 `status` 从 `R1-inventoried` 改成 `R10B-aware` 就只是改一次字符串。
> R11B 有 787 文件 / 263,763 行 L3 等着排期,而排期需要先知道「一片 L3 要交什么」。

## 判据本身

L3 的定位是**「知悉用途」**:知道这里有什么、有多大、谁用它、动它要动哪些,
**不要求**知道它每个符号叫什么。所以判据不是 L2 判据的削弱版,而是换了一组问题。

| # | 判据 | 可复核方式(机械优先) |
|---|---|---|
| **L3-1 用途到位** | 片内**每个**文件至少出现一次**全路径** + 一句话「它是什么、谁读它」。同型薄文件可归组,**组内仍逐个列全路径** | `data/r10/probes/named_coverage.py` 报出**全路径零命中**与**裸文件名零命中**两个数,均须为 0 |
| **L3-2 形态账** | 把片内文件按**形态**分组(如「数据表」「运行时装配」「类型契约」),每组给出**机械可复算的规模数**(文件数 / 行数 / 条目数)**与得出它的命令**。**不要求穷举接口面**——那是 L2 判据 2 | 重跑你给的命令,核对数字 |
| **L3-3 一条真链** | 至少一条「这份东西被谁读 → 在哪装配 → 缺了会怎样」的链,**逐跳带锚点**。比 L2 判据 3 弱(不必到界面),但必须证明**顺着代码看过**,而不是只看了目录树 | 顺锚点走一遍 |
| **L3-4 逐字取证下限** | 至少 **2** 个围栏块是逐字源码摘录,**且必须钉在 L3-3 那条链的关键跳上**,不是随手摘一段数据 | BLOCK-DRIFT 全块比对 + 人工看它摘的是不是链上的跳 |
| **L3-5 记号或有搜索面的负结论** | 至少一条 ■/▲/◇/◎ 带锚点;**或者**明确写「本簇未发现」并**给出搜索面**(搜了什么、什么模式、排除了什么) | 抽验证据;负结论看搜索面写没写 |

## 三条口径说明(定这几条的理由,便于后续轮有意推翻)

**(a) L3-4 不按行数比例加码。** L3 片的行数常常主要是**数据**(本轮 slice I 的
17,378 行里,5 个语言包 + 1 个类型文件占 16,811 行,全是字符串表)。
要求「每 N 行摘一段」只会逼人摘翻译表,而**逐字摘一段翻译表证明不了任何事**。
所以下限固定为 2 块,并且要求它们钉在链上——**要的是链可信,不是摘录多**。

**(b) L3-2 用「形态账」替掉 L2 的「接缝穷举」。** L2 那条的理由是
「可以不读实现,但不能抽样接口」——接口抽样了,结构级理解就退化成看过几个文件。
L3 没有这个风险,因为 L3 本来就不承诺理解接口;L3 会退化成的样子是
**「我列了个目录」**。挡住这一种退化的,是要求给出**规模数与算它的命令**:
目录谁都能列,「`en.ts` 有多少个叶子键、命令是什么」列不出来就是没打开过。

**(c) L3-5 允许负结论,但要付搜索面的成本。** L3 片经常真的没有缺陷可报
(一个语言包能有什么缺陷),强行凑一条 ■ 比不报更糟。但「没发现」和「没找」
在报告里长得一样,所以走项目既有的那条规矩:**全称否定必须写出搜索面**。

## 与 L2 五条的对照

| | L2(R10 定) | L3(R10B 定) |
|---|---|---|
| 点名 | 判据 1:全路径 + **角色** | L3-1:全路径 + **用途/谁读它** |
| 广度 | 判据 2:**接缝穷举,不抽样** | L3-2:**形态账 + 规模数 + 命令**(不要求穷举接口) |
| 深度 | 判据 3:端到端链(到界面) | L3-3:一条**被谁读→在哪装配→缺了会怎样**的链 |
| 取证 | 判据 4:≥2 个逐字块 | L3-4:≥2 个逐字块,**且钉在链上** |
| 判断 | 判据 5:≥1 条记号 | L3-5:≥1 条记号 **或** 带搜索面的负结论 |
