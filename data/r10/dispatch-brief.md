## 1. 铁律(违反即作废)

## 2. 证据格式(有脚本机械校验,不合格会被打回)

- 凡对 hermes-agent 行为的断言,紧跟锚点 `路径:行号 @ 863e313`。
- **锚点一律单独成行,置于代码块之前**,不写在块后、不塞进块里。
  校验器按「锚点 → **紧跟其后**的块」配对。
- ` ``` ` 围栏块 = **逐字源码摘录**,且**整块每一行**都会与基线逐行比对
  (空白不敏感、文字必须逐字一致)。抄漏半行注释、把多行调用压成一行、
  凭空补一个 `"""` 收尾,都会被判 BLOCK-DRIFT 而**阻断**。
  **要跳段就拆成两个各自带锚点的块**,不要打省略号 —— 省略号之后的内容会失去校验。
  **强烈建议**:用 `sed -n 'A,Bp' 文件` 把源码取出来再粘贴,不要手抄。
- 非源码的内容(命令回显、你自己的表格、推演、示意)必须用
  ` ```text ` / ` ```verify ` / ` ```console ` 围栏**声明**。
- 凡把 shell 命令写进证据,**必须是重跑能复现该结论的那一条**,用 ` ```verify ` 围栏。
  *(历史教训:有一条自检 grep 用 `iron` 匹配到了 `env`**`iron`**`ment`,
  重跑对每个文件都命中,与它声称的"零命中"相反。一条重跑给出相反结果的命令比不写更糟。)*
- `>` 引用块用于文档摘录或转述。
- **表格里提到代码时**,写成「锚点 + **紧跟其后**的反引号摘录」才会被校验,例如:
  `| ... | ` + "`web/src/lib/api.ts:120`:`export async function listSessions()`" + ` | ... |`
- 引用**必须能从仓库根解析**:不写裸文件名(`api.ts:120` 是谜题,`web/src/lib/api.ts:120` 才是引用)。
- **负结论(「全仓没有 X」「没有第三个调用方」)必须把搜索面写出来**:
  搜了什么、用什么模式、排除了什么。否则它只是「我没看见」的另一种说法。
  *(历史教训:一条"没有第三个读原始配置后落盘的调用方"的负结论关闭了调查,
  而漏掉的那个会在坏 YAML 下把用户的审批黑名单静默抹掉。
  **正结论错了会被下一个读者撞见;负结论错了会关闭调查。**)*

## 3. 记号

| 记号 | 含义 |
|---|---|
| ■ | 代码缺陷 |
| ▲ | 文档所述与代码**矛盾** |
| ◇ | 代码有、文档无 |
| ◎ | 文档成立但显著保守(如"20+ 平台"而实为 24) |

**字面为真就不是 ▲。** 判定一条文档断言时必须把它所在的**整句/整段**一并判定,
并确认它归**哪个标题**管 —— 文档的层级结构本身就是断言的一部分。

## 4. 本轮是 L2「结构级理解」,不是 L1 机制精读

L2 与 L1 的真实差别**不是"读得浅"**,而是**"读接口面而不读实现体"**。
一个 14,006 行的文件,L1 的做法是逐个方法读实现;L2 的做法是把方法表列全、
把生命周期与并发模型讲清,把实现体留给需要时再下钻。
**所以 L2 可以不读实现,但不能抽样接口。**

### 交付判据(五条,逐条自检并在底稿 §8 自评)

1. **点名到位**:片内**每个文件**在底稿里至少出现一次**全路径**,并有一句话角色说明。
   同型薄文件可归入显式命名的组,但组内**仍要逐个列出全路径**。
2. **接缝穷举**:片内每个对外接缝(JSON-RPC 方法表 / HTTP 端点表 / IPC 通道表 /
   包导出表 / 事件类型表 / 命令表)必须**逐项列全、不抽样**,
   并给出**机械枚举命令**(` ```verify `)与条数。
3. **一条端到端链走通**:至少一条从用户动作 → 客户端 → 协议 → Python 内核 → 回到界面的
   调用链,**逐跳带锚点**。跨不出你这一片时,把你这一片内的那一段走通,并写清两端接到谁。
4. **两处以上逐字取证**:至少 2 个围栏代码块是逐字源码摘录。
5. **至少一条记号**:至少一条 ■/▲/◇/◎,带锚点。
