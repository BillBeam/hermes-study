# R11E 派工书(三片,批次一同时派发)

> **为什么这份文件存在。** `data/rNN/dispatch-brief.md` 是 R10 / R10B / R11A / R11B / R11C
> **连续五轮**的惯例;R11D 没留,R11E 起初也没留。片 C 复查 `H-R11C-C-b`
> (「证据块不得依赖另一个块产生的文件」是否写进了下一轮派工书)时因此判为
> **无法机械核验** —— 一条要求「写进派工书」的移交项,遇到一个不落库派工书的轮次,
> 就永远停在「查不了」。本文件把 R11E 三份派工书的**约束条款**落库,恢复该惯例。
>
> **口径要如实说**:派工书是以会话消息形式发出的,本文件是**事后誊录**,
> 誊录的是**全部约束条款与产出要求**(即会被后续轮次核验的那部分),
> 不含派工时的背景铺陈。誊录时间:本轮收官前,三片均已交付。

## 三片共用的硬约束(逐条写进了每一份派工书)

1. **`chapters/` 一个字节都不许改**,只读。同样不许改 `scripts/`、`CLAUDE.md`、
   `data/ledger.tsv`、`data/chapter-order.tsv`、`data/round-registry.tsv`,
   以及 `/home/user/hermes-agent`(基线只读,不许写不许 checkout)。
2. **只写自己名下的文件**(见上表)。片 C 另许写 `data/r11e/probes/handover_*.py`。
3. **不许运行任何 git 写操作**(commit / add / checkout / stash / push)。只读的
   `git log` / `git show` / `git grep` 可用。
4. **不许安装任何包**(pip / apt / npm / 任何全局工具链)。理由写进了派工书:
   共享 venv 的包数是报告要报的数,装一个包就让开工/收工两个读数不可比。
5. **执行基线代码一律带 `HERMES_DISABLE_LAZY_INSTALLS=1`**(基线的可选依赖是惰性联网安装的)。
6. **凡正文里出现「实测 N 处」这类由某条命令得出的数,那条命令要写进 ```verify 围栏,
   紧跟其后贴 ```text 围栏放它的逐字输出。** —— 这一条就是 `H-R11C-C-b` 所要求的
   「写进下一轮派工书」的那一族要求;三份派工书均含此条。
7. **负结论必须写搜索面**:搜了什么目录、什么模式、排除了什么。
8. **完成信号只写在底稿末尾的 `## 完成信号` 一节;不许自己去改
   `data/inflight/*.claim`** —— 关闭 claim 是消费者(主线)确认收到信号的动作,
   生产者自己翻牌等于守卫可以自解锁(R11C 实测过这个违例)。

## 片 A / 片 B 专有约束

- `group` 只能取**固定十格词表**:`模型与推理调用` / `工具与执行` / `会话、状态与上下文` /
  `接入与多平台` / `配置与凭据` / `安全、权限与边界` / `可靠性、故障与恢复` /
  `部署、运维与升级` / `界面与客户端` / `工程方法与项目治理`。
  放不进任何一格时填 `NEW:<提议>` 并在底稿说明理由,**由主线裁定,不许自造**。
- `problem` 必须是**症状式问句**,以问号结尾;**入口必须是问题,不是模块名**。
- `section` 必须**逐字复制**该章某一行 `## ` / `### ` 标题的标题正文;**H3 优先**。
- 底稿必须含**逐章覆盖表**(每章全部 H2/H3 标注已指向/未指向),未指向的逐个说明原因。
- 交付前跑派工书给定的自校验脚本(列数 / 标题解析 / 问句 / 坏行数)。

## 片 C 专有约束

- 归属判据三条(去向点名阅读层 / 本轮产物范围内自然做掉或证伪 / 关于成品章可读性与
  派生件同步),**判不了就归入「存疑·交主线裁定」**。
- `verdict` 五选一:`本轮结清` / `本轮部分结清` / `不归属本轮·转R12装订` /
  `不归属本轮·转内容轮` / `存疑·交主线裁定`。**明令不许写「续转」。**
- `anchor` 必须用**声明式写法**(`路径:行号` 后紧跟反引号摘录),否则校验器只会记
  TABLE-UNCHECKED。
- 派工书明确告知了现成普查工具的**三个已知缺陷**(案号正则匹配不了三段式片内号、
  定案表把它定的案重新打开、认不出的表头被静默丢弃),并要求
  **先跑普查拿候选面、再人工逐条核**,不许把普查输出当结论。
- 引 R11C 定的一条:**机械判据不得用词根去判「开/闭」这类语义**(R11C 的词根表
  13 条命中里 6 条是假阳性,全部栽在「短语被从它的否定里摘出来」)。

## 事后评价:哪几条约束真的起了作用

- **第 6 条(数必须配输出块)**:三片合计 `paired=19 unpaired=0 differing=0`。
  没有这一条,子代理底稿默认不配对,关卡覆盖面会停在个位数百分比。
- **第 8 条(不许自关 claim)**:三片全部遵守,claim 均由主线在复核后关闭。
- **词表统一**:两片各 100+ 条,`NEW:` 提议 **0** 个,合并时零词表冲突。
  但**措辞不统一**——两片 233 个问题里逐字相同的 **0** 个,合并需要一张归一化表。
  下次派同类任务时,值得把「元问题的逐字文本」也一并给死。
- **没起作用的一条**:派工书要求片 A/B 报覆盖率,两片各自报了 84.4% 与 77.4%,
  口径是「本片章范围内」;主线合并后按全 21 章算是 81.5%。**三个数都对,但派工书
  没规定口径归一**,于是三个数摆在一起需要额外解释。
